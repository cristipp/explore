SOTA factoring

Each model writes the best factoring program it can in 1 h; the programs are graded afterwards.

Hypotheses, stated before the runs: (1) a competent coder converges on the state of the art whatever the constraints: with libraries it calls the best library, with references but no libraries it implements the best algorithm, and from training data memories alone it still implements the best algorithm. (2) Above a competency threshold, the model doesn't matter. To test both, Sonnet 5.5 medium and Opus 5.5 max each ran under three conditions (L, R, M below).

Verdict: (1) supported; (2) mostly: the model matters, but by a thin margin. (1) All six runs built a self-initialising quadratic sieve, the standard best method at these sizes. Opus with libraries used the rusqsieve crate and reached 41 digits per prime; with no web and no crates both models reached 40. No run used the web, yet the web, no crates condition (R) changed behaviour: both R runs stopped after about 20 minutes (Sonnet 19, Opus 21), against 38–52 minutes for the other four, and scored at or below their no-web, no-crates twins (Sonnet 37 vs 40, Opus 40 = 40). (2) Opus max is at or above Sonnet medium in every condition, by 0 to 3 digits per prime: anything goes 41 vs 39, web, no crates 40 vs 37, no web, no crates 40 = 40. All six land within 37–41. What differs is the solution each model chose and how long it took to write it (19–53 min).

What each model built

Each model had 1 h to write the best factoring program it could, in Rust, with the grading rules stated up front. L = anything goes (any crate + web), R = web, no crates (web allowed but never used; std + the big-int whitelist), M = no web, no crates (std + a small big-int crate whitelist). Programs differ only in which solution the model chose and how long it took to write; the chart below checks that their runtime performance is indeed similar.

Hardware: the models ran as Claude Code sessions in the cloud, but built, benchmarked and tuned their programs on this machine, a MacBook Air with Apple M4 (10 cores) and 32 GB. Grading ran afterwards on the same machine, idle.

Sonnet M uses no crates by accident: it asked for num-bigint 0.4, only 0.5.1 was pre-fetched, and after the offline build failed it wrote its own big-integer code instead of switching versions. The rules are the rules, so the run counts as is.

How the programs were built and how they run
