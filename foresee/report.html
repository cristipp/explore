Can you foresee what a program will do without running it?

Report, 6 October 2026. Starting point: two sentences from Stephen Wolfram's essay "Towards a Theory of Bugs: The Ruliology of the Unexpected" (21 July 2026), as quoted on X by @michael_timbs, who asked what Wolfram meant.

"if you can completely foresee what a program will do, what's the point of running it? Why not, in effect, just immediately 'write down the answer', without ever having to run the program? […] once there's anything you can't foresee, there tends to be a lot you can't foresee."

Questions this report answers

  • What does "foresee" mean, precisely? (section 1)
  • The halving rule: could one program run every long program in half the time? (section 1)
  • The tower: aim the halving foreseer at its own runs. Does evaluation length collapse? (section 1)
  • The ladder: what is proved, conjectured, or a thesis about irreducibility? (section 3)
  • Is the Principle of Computational Equivalence proved, or a thesis? (section 4)

The answer in one picture. Wolfram's second sentence can be read two ways. The worst-case reading reaches a theorem in its second step. The density reading, which is what his words say, reaches none.

The theorem (section 1): no general foreseer exists, not even one that just halves the time. It is an existence result, like "irrational numbers exist". Wolfram's "a lot" is about how much of a system's behaviour is unforeseeable, a density question that no theorem reaches (section 2).

1. The theorem: no general foreseer

Definition. Fix a machine model (multi-tape Turing machines). A program F foresees the run of program P on input x with speedup s if it produces the same output in at most

t(P, x) / s  +  c · |⟨P, x⟩|  steps,

where t(P, x) is the length of the run, ⟨P, x⟩ encodes the question, and c is a constant belonging to F: any method has to read the question. F foresees a set of runs if one F with one s > 1 works for all of them.

The order of the quantifiers decides everything:

  • One run: always foreseeable, by "print the answer", Wolfram's "write down the answer". But someone had to compute it.
  • One program, all inputs: foreseeable up to any constant factor, by a bigger twin program (the linear speedup theorem, Hartmanis & Stearns 1965). So "completely foresee what a program will do" must mean an asymptotically faster shortcut, and whether one exists is a question about that program. Rule 90 has one; for Rule 30 nobody knows (try it below).
  • One foreseer for a whole class of programs: impossible, as soon as the class is rich. That is the theorem.

Try it: a shortcut and a mystery. Both cellular automata start from one black cell. Rule 90 is Pascal's triangle mod 2, so by Lucas's theorem any cell at any step is one bit test, even at step 1018. Rule 30 has no known shortcut: its centre cell at step n takes about n² cell updates to simulate. Whether order n work is unavoidable is Problem 3 of Wolfram's 2019 Rule 30 Prizes, still open.

The halving rule

Halving rule. One program F and a constant c such that, for every P and x:
    F(⟨P, x⟩) = P(x)   in at most   t(P, x) / 2  +  c · |⟨P, x⟩|  steps

It sounds modest: half the time, plus the time to read the question. But F is itself a program, so the rule applies to F's own runs.

The tower: aim the foreseer at itself

Feed F a description of F foreseeing P, then of F foreseeing F foreseeing P, and so on. Each level adds one copy of F's code to the input and halves the time:

y₀ = ⟨P, x⟩,   yₖ₊₁ = ⟨F, yₖ⟩,   |yₖ| ≤ |y₀| + k·(|F| + d)
aₖ = time(F on yₖ)  ≤  aₖ₋₁ / 2  +  c·|yₖ|
after k = ⌈log₂ T⌉ levels:   aₖ  ≲  1 + 2c · ( |y₀| + (|F| + d) · log₂ T )

⟨F, y⟩ must be a self-delimiting code for F followed by y verbatim, so each level adds only a constant d.

Why F can't exist. Every T-step computation would collapse to its reading time plus a log T term. But the time hierarchy theorem (Hartmanis & Stearns 1965; Hennie & Stearns 1966) builds, by diagonalization, a problem that some program solves in n³ steps and no program solves in n². Stack ⌈3 log₂ n⌉ levels on that program and the tower solves it in about 2c·(n + 3|F|·log₂ n) steps, a contradiction. The same argument rules out any fixed speedup s > 1. It works because the saving is a fraction, which compounds, and the foreseer is one program, which can be aimed at itself. So, to the tower question: evaluation length would collapse to reading time, and that collapse is why the premise is false.

What exactly is claimed. The tower works for any class C of programs that contains the foreseer's own runs on members of C and is rich: it contains problems that provably need much more time than reading their input.

Ruled out, for any fixed speedup: one foreseer for all programs; for all programs within a time bound such as n² steps; a universal program halving its own runs; one foreseer for every starting condition of an efficiently universal system like Rule 110.

Not ruled out: foreseers for classes too weak to contain the foreseer (Rule 90, finite automata, loops with closed forms); a shortcut for one fixed computation, such as Rule 30's centre column; foreseers that are fast on most programs rather than all. In short: no foreseer for a class rich enough to contain the foreseer itself, and no claim about weaker classes, single systems, or how common unforeseeable runs are.

2. How much is "a lot"?

Wolfram's words are a density claim: the system "will tend to be full of computational irreducibility", with pockets of reducibility in between. He presents this step as intuition from the Principle of Computational Equivalence (section 4). The theorem is an existence claim. The gap is the one between the rationals and the reals, and it starts with "a lot" having several inequivalent meanings:

"a lot" measured bythe rationals inside the reals
presence: in every interval?yes, the rationals are dense: every interval contains one
measure: chance that a random point lands in the setzero: a random real is irrational with probability 1
countcountably many, against uncountably many reals

These can disagree in every direction: the Liouville numbers are "almost all" reals in the topological sense (a comeager set), yet they have measure zero. In these terms:

  • The theorem is a "not every real is rational" statement. Unforeseeable runs exist in every rich class; it says nothing about their measure.
  • Universality gives variety, not density. A universal system contains every computation somewhere, possibly only on a measure-zero set of carefully built starting conditions, as in Rule 110's universality proof. "Once there's anything" behaves the same way: computing one hard function means computing everything reducible to it. Breadth, not bulk.
  • Wolfram's picture is "the irrationals have full measure". Irreducibility is the bulk; pockets of reducibility are like the rationals, present everywhere but small. The PCE's "almost all processes" is a density claim across systems; "full of irreducibility" is one within a system.

Programs are countable, so "almost all" needs a chosen measure, and the answer depends on the choice:

  • Worst-case hardness can be generically easy. The halting problem is decidable on a set of programs of asymptotic probability one (Hamkins & Miasnikov 2006): their machines have a one-way tape, and almost all of them soon run off its end and stop. The authors stress that this depends on the model. Many undecidable problems about groups are likewise easy on almost all inputs (Kapovich, Myasnikov, Schupp & Shpilrain 2003).
  • Where a canonical measure exists, hardness is typical but universality is rare. Problems, as infinite sequences of yes/no answers, form an uncountable space, the "reals" of this story, and Lutz's resource-bounded measure makes "almost every problem in exponential time (E)" precise. P has measure zero in E (Lutz 1992), and almost every problem in E resists polynomial-time shortcuts on every infinite, efficiently recognizable family of its inputs (Mayordomo 1994). But the problems hard for E, the complexity-theory analogue of universality, form a measure-zero set (Juedes & Lutz 1995). The typical hard problem is intermediate, the opposite of the PCE's "no natural intermediates".
  • The PCE's best reply. Those typical problems are random noise. Nature runs short rules, and short rules are like the computable reals: countably many, measure zero, yet the only ones anyone can name. What is typical among simple rules has no canonical measure and no theorems, only Wolfram's enumerations.

Our experiments (section 5) point the same way: in Wolfram's own bug experiment, late surprises exist but quickly become rare, and pockets of exact coarse-grained foresight turn up in most elementary rules, though not in Rule 30.

So the density claim, the one Wolfram actually makes, is not reached by the theorem and not implied by universality, and where measure theory can speak, it speaks both ways. It stands or falls with the PCE as a thesis about simple rules.

The first three rungs are worst-case theorems; the next two are density theorems, and they point in different directions. The Rule 30 rung is a precise open conjecture. The last is a thesis that only evidence can support.

4. Is the Principle of Computational Equivalence proved, or a thesis?

The Principle of Computational Equivalence (PCE), from A New Kind of Science, ch. 12: almost all processes that are not obviously simple "can be viewed as computations of equivalent sophistication" (pp. 716–717). As stated it can't be proved: "almost all" has no measure and "obviously simple" no definition. Wolfram presents it as partly a law of nature, partly an abstract fact and partly a definition (p. 719). Its premise is "not obviously simple", not "unforeseeable"; reading his bug sentence as "unforeseeable ⇒ universal" is our gloss.

Mathematics says it is false in principle and true in practice:

  • False in principle. There are undecidable problems strictly weaker than the halting problem (Friedberg 1957; Muchnik 1956) and, if P ≠ NP, problems strictly between easy and NP-complete (Ladner 1975). Wolfram's reply (NKS p. 1130): these constructions only look at outputs, and have universal components inside.
  • True in practice. Natural undecidable problems turn out exactly as hard as the halting problem (Montalbán 2019), and natural NP problems are almost always either easy or NP-complete; for constraint satisfaction problems that dichotomy is a theorem (Bulatov 2017; Zhuk 2020). Factoring and graph isomorphism remain candidates for in-between, not proven ones.

The evidence for it: universality appears at strikingly low thresholds, in Rule 110, the Game of Life, tag systems, tiny Turing machines and Diophantine equations. Note that the PCE promises equivalent power, not the efficient universality that the theorem needs.

Verdict: a thesis, and a well-supported one, in the sense of the Church–Turing thesis: it ties an informal notion to a formal one, so evidence can support it but no proof can settle it. It is false as a precise theorem, plausible as a regularity of the systems nature produces, and, as section 2 shows, unproven in exactly the density form that Wolfram's sentence needs.

5. Two experiments: bugs and pockets

Wolfram's bugs, rerun. His essay enumerates tiny Turing machines (s states, two colours, input n in binary under the head, output read when the head moves right of its start) and asks which ones add 1. We tested all (4s)2s of them, 4.3 billion for 4 states, on n = 1…255, and match his counts: 8,934 three-state and 9,335,700 four-state machines are right on every input tried, and 222 four-state machines are right up to 62 but wrong at 63 (one answers 72, as in his essay). Late bugs sit at inputs like 7, 15, 31, 63, where the carry travels furthest.

Each doubling of the test depth cuts late failures by a factor of 5 to 70. Testing can miss, which is Wolfram's point, but rarely, which is not "a lot". The caveats: tiny machines, a simple task, inputs only up to 255.

Code: a 100-line C program that branches on a rule-table entry only when a run first needs it, about 20 minutes for the 4.3 billion machines. "Never stops" means no halt within 20,000 steps.

Pockets of reducibility. Group a cellular automaton's cells into blocks, summarize each block by one bit, and look for a rule that predicts the summaries exactly (Israeli & Goldenfeld 2004). Searching all 256 elementary rules with blocks of up to 4 cells, 202 rules have such a coarse-graining, 108 of them onto a different, non-constant rule.

Rule 146 looks chaotic, yet its all-black blocks of 3 follow trivial Rule 128. Universal Rule 110 has only the weakest kind: with blocks of 5, the block 01010 never appears after five steps. Rule 30 has none, not even the weak kind at any block size, because it is surjective: no block is ever ruled out. Pockets are everywhere, like the rationals, but Rule 30 offers none we could find.

Two more kinds of foresight survive: properties, which a proof can predict for every output without computing one (formal verification lives in these pockets), and statistics, such as Rule 30's centre column looking half black, though even that is unproved (Rule 30 Prize problem 2).

6. Bottom line

Wolfram's first sentence is close to a tautology: a program with a shortcut isn't worth running. Its precise companion is a theorem: no general foreseer exists, not even one that just halves the time, so programs worth running always exist. That is an existence result. His second sentence is a density claim, that a complex-looking system is full of irreducibility. No theorem reaches it, measure theory cuts both ways, and our bug data shows surprises that exist but are rare. It rests on the PCE: a well-supported thesis about simple rules, not a theorem.

Terms

Turing machine
The standard model of a computer: a finite rule table reading and writing symbols on an unbounded tape, one cell per step. The multi-tape version is the usual model for counting steps.
cellular automaton
A row of black and white cells updated in parallel by one rule. In an elementary one, a cell's next colour depends on itself and its two neighbours: 256 possible rules (Rule 30, Rule 90, Rule 110, …).
universal
Able to emulate any Turing machine, given a suitable encoding of the machine and its input in the starting condition.
efficiently universal
Universal with only polynomial overhead in encoding size and running time. The theorem needs this; exponential overhead is not enough.
computationally irreducible
Wolfram's term: no way to predict a system essentially faster than running it (NKS p. 739). A property of one system; the theorem is about a different notion, no uniform speedup across a class.
P, NP, E
P: problems solvable in polynomial time. NP: problems whose solutions can be checked in polynomial time. E: problems solvable in time 2O(n). P ≠ NP is the famous open problem.
NP-complete
The hardest problems in NP: a fast algorithm for one would give fast algorithms for all of NP.
P-complete
The hardest problems in P under very cheap reductions: if one had a fast parallel algorithm (in NC), all of P would.
NC
Problems solvable in polylogarithmic time with polynomially many parallel processors. Whether P = NC is open.
diagonalization
Building an object that differs from every item on a list, such as a problem that every fast program gets wrong somewhere.
halting problem
Deciding whether a given program stops on a given input. Turing proved no program can do it in general.
Lucas's theorem
C(t, k) is odd exactly when every 1 bit of k is a 1 bit of t; it turns Rule 90 into a bit test.
surjective
A cellular automaton is surjective if every row has a predecessor; equivalently, no finite block is ever ruled out.
measure zero, almost all
A set has measure zero if a random point lands in it with probability 0, like the rationals in the reals; its complement holds almost all points. On a countable collection such as all programs there is no canonical "random", so such claims depend on the distribution chosen.
comeager
"Almost all" topologically: containing a countable intersection of dense open sets. It can disagree with measure: the Liouville numbers are comeager yet have measure zero.
asymptotic probability
The fraction of inputs of size n with a property, in the limit of large n. A problem is generically easy if it is solvable on a set of asymptotic probability one.
resource-bounded measure
Lutz's version of "almost every problem in E": a set has measure zero in E if some betting strategy computable within E wins unboundedly against every member.
Church–Turing thesis
Everything effectively computable is computable by a Turing machine: an informal notion tied to a formal one, supported by evidence, not provable.
